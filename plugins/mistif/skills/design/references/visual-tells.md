# Visual tells

A tell is a pattern so common in machine-made pages that it signals "nobody decided this". One tell is fine if it earns its place; a cluster is the problem.

| Tell | Instead |
|---|---|
| a violet-to-blue glow behind the hero | one flat or textured background that matches the product's world |
| frosted glass on every panel | solid surfaces; glass for one layer that really floats |
| the same corner radius everywhere | a radius per role: controls, cards, media |
| the stock section order (hero, three features, logos, pricing, call to action) | the order the visitor's questions come in |
| a row of identical cards | cards that differ in size or content where the content differs |
| a strip of decorative statistics | one real number in context, or none |
| gradient text on a heading | weight and size contrast |
| stock icons in coloured circles | no icon, or one drawn for this product |

## App screens
- Start from the decision the user makes on this screen and put the information for it first.
- Navigation, filters and tables come from the real data, not a template.
- Empty, loading and error states are designed, with the cause and the next action.

## When a fix leaves a hole
Add one thing with intent: a focal point, a stronger type scale, a single accent colour used once, a repeated shape.
