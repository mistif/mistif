# Full skill comparison: Phase 1 result (2026-10-24)

Skills from an earlier mistif build (before 1.0.19). All tables were generated by an analysis script from the run records. Raw run outputs, answer keys and the harness scripts are not part of this repository (to keep it small); this report and its tables are the evidence.

## Answer in five lines

1. **New beats old, and old does nothing.** With the model sent to its skills (primed arm, 3 models x 10 tasks x 2 runs): new Full 4.04 / 3.78 / 4.05 (Sonnet / Haiku / Opus) vs old 3.67 / 3.65 / 3.68. Paired new minus old = **+0.29** (95% interval +0.14 to +0.45, 60 pairs), at **23k fewer tokens and $0.05 less per run**. Old minus no skills = +0.04 (-0.09 to +0.17): the old set bought nothing measurable.
2. **New vs no skills: +0.33** (+0.16 to +0.50). Opus gains most (+0.53), Sonnet +0.32, Haiku +0.15 (not distinguishable from 0). The gain is big for fan-out, prompts and decisions, small or zero for review, ship, UI, build.
3. **Lite = Full on quality** (-0.03, -0.18 to +0.12) at **17k fewer tokens per run** (Opus -39k, Sonnet -14k, Haiku +1k). Worth shipping as the option for Opus.
4. **Entry-only (E) does not work as built.** The `mistif` entry fired, but it reached the intended role skill in only **2 of 20** runs (C: 18 of 20). Score -0.29 vs C (-0.66 to +0.05), about equal to no skills. The entry sizes the task as small and does it inline.
5. **Skills only help if they are loaded, and models do not load them on their own.** Without the "use the skill that fits" line, Sonnet loaded a skill in 1 of 20 runs (new) and 0 of 20 (old). Part of the benefit still arrives through the listing alone (descriptions mention "GO / TEST FIRST / NO-GO", and unprimed new beat none by +0.29), which is a cost-free effect of a good description.

Not clear / not tested: **mistif:interview** (see section 6), per-skill ranking below about 0.6 (noise), and Opus vs other models (Opus is judged by a weaker judge).

## 1. What was run

340 headless runs (`claude -p`, clean profile, no user settings/plugins/MCP, 8 tools; verified per run from the init event, `cond_ok` true in all 340):
- **Primed arm (main)**: 10 tasks x {Haiku, Sonnet, Opus} x {A none, B old, C new Full, D new Lite} x 2 runs = 240, plus E (entry only) on Sonnet = 20. The prompt starts with a neutral line, identical in every condition: "look at the skills you have available and use the one that fits this task, if there is one", and ends with "no user is available: state your assumption and continue".
- **Unprimed arm**: plain brief, Sonnet only, 10 tasks x A-D x 2 = 80.
- Tasks: T1 shaping, T2 build, T3 review (10 planted issues + 3 decoys), T4 ship (12 planted risks), T5 UI page, T6 decision, T7 prompt rewrite, T8 tests for a bug, T9 tests for legacy code, T10 fan-out trap. Briefs in `tasks.json`.
- Judges: Opus for Haiku and Sonnet outputs, **Sonnet (weaker) for Opus outputs**; one packet per task and model with all runs under shuffled labels; two passes with different shuffles; 3-4 stated criteria; packets hold the final message, a diff of everything the run created, the harness-measured facts, the planted-issue list for T3/T4/T10, and for T5 the 390 px and 1280 px screenshots (real CDP device emulation, judges opened them). Every judgment quotes a detail from the files (`seen`). Measured instead of judged: hidden tests (T2), fails-on-buggy / passes-on-fixed / 9 mutants (T8), passes-on-original / 14 mutants (T9), agents spawned (T10), page written (T5).
- Cost by the CLI: runs $49.76 (primed Haiku $0.88, Sonnet $13.04, Opus $26.68; unprimed Sonnet $9.17); judging $20.58 kept plus $7.85 re-run; about $78 in all (projection was about $80).

## 5. Which model, per skill (for the lean-agents table)

Quality threshold: a model "held" if its mean in condition C is within **0.30** of the best model's mean in that row (0.30 is one standard error of a difference between two 2-run cells, SD 0.29 per run). Noise: judge pass to judge pass 0.24, run to run 0.33 (SD about 0.29). Opus is judged by a weaker judge, so "Opus no better" is the safer claim than "Opus better".

Skill actually loaded (primed): Haiku, Sonnet and Opus each loaded the intended new skill in 18 of 20 C runs (all except the two-run shaping task, where none did) and the old counterpart in 14, 16, 15 of 20 B runs. **Unprimed, models do not load skills on their own** (Sonnet 1 of 20; Haiku 0 of 3 and Opus 0 of 2 in the pilot probes), so "which model" matters less than "is the skill pointed at".

Rule of thumb: (1) Use Haiku for review, ship, tests, prompts, decisions and UI once the skill is loaded; Sonnet for build and anything that must obey a "do not spawn" rule; Opus buys nothing measurable for any of these and costs 2.5-3x Sonnet and more than 20x Haiku. (2) Point the model at the skill (the skill does not load itself in a plain request, on any model). (3) Haiku can load a skill and still ignore it (fan-out): never rely on Haiku for rules that restrict behaviour.

## 6. Method issues found and fixed during the run (all disclosed; no skill touched)

1. **My diff capture missed committed work**: 16 runs committed on a branch and had an empty diff, so judges saw only the final message. Rebuilt every `changes.diff` from the final files vs the fixture (`rediff.py`) and re-judged the 10 affected packets. This is the same class of bug as the earlier empty-diff problem; the packet builder now refuses empty diffs for code tasks.
2. **pytest measuring was wrong on 23 of about 170 runs** (collection errors from a stray parent config; not reproducible by hand). Pinned the pytest root, re-measured all 170, confirmed a repeat of 10 gave identical values, and re-judged the 14 packets whose measured facts had changed (`measures_v1/` keeps the first values). Run-to-run noise fell from 0.41 to 0.33 after this.
3. **T2 mutation measure dropped**: my reference implementation disagreed with legitimate design choices (rejecting `30m1h`, non-strings), so it penalised good tests; T2 is scored by the 22 hidden cases plus the judge, and its judge packets were redone without that fact.
4. **Operational**: a Windows cleanup crash, 4 Opus runs and 2 Haiku runs that timed out or were killed were re-run (results deleted and repeated); no scored run is a failed run.
5. **Test limits**: T1 cannot test an interview skill when nobody can answer (all conditions build the app); the measured checks still saturate on some tasks (T4/T8 scores near 4.1-4.5 for all conditions); 9 and 14 mutants were killed by most test suites. A **description-only effect** exists (unprimed, no skill loaded: new beat none by +0.29), so "skills vs none" includes the cost-free effect of the listing text. Built-in Claude skills (about 22) are in every condition. D includes the three-file Lite edit from an earlier commit plus the Lite line; E hides every skill except `mistif` with `disable-model-invocation: true` (verified: a model lists only `an earlier plugin:mistif`).

## 7. What to fix next (ranked)

1. **mistif:design: never invent content.** Sonnet's pages added made-up numbers, tool names and claims while the brief gave exact facts; also keep text at 12 px or more and tap targets at 44 px. Largest visible loss against the old set and against plain Claude.
2. **Entry-only (E) needs a path-based hand-off or must stay off.** The entry skill should load the chosen role skill (it never does for "small" tasks, and the Skill tool cannot load hidden skills). Until then keep the 10 skills listed (the listing costs about 1.3k tokens).
3. **lean-agents must hold on Haiku**: Haiku loaded it 2/2 and still spawned 13 agents. Put the decline rule as the first line, and test Haiku on it after the change.
4. **Ship Lite for Opus** (-39k tokens, -0.03 quality) and consider it for Sonnet (-14k, -0.13, not significant).
5. **mistif:build on Haiku** scored 0.3 below no skill: shorten the first screen of the skill or route Haiku to a lighter path.
6. **mistif:interview is never reached on a vague request** (0 of 6, while the old spec skill was loaded 6 of 6): mistif:build's description says vague requests go to the interview first, but models start building; make that the first line of the build skill and of the entry. Also it needs an interactive test; and when nobody can answer, say in one line "build nothing, give the brief and the assumptions" (the unattended shaping task cost $0.25-$0.86 per run on Sonnet/Opus in every condition, including with the skills).
7. **Cheap win**: keep the listing text (it alone moved Sonnet +0.29 unprimed); do not lengthen it.
8. **mistif:review is neutral vs no skill**: not worse, not better. Decide whether it earns its tokens or should focus on what plain Claude misses (the planted decoys, the severity order).
